# Rule: Open a PR on Github

## Goal

To open a PR on Github for the current branch in draft mode. The description of the PR should be casual, but professional. It should clearly state the following:

- The problem the changes solve
- How the changes address the problem
- Any supporting documentation or links

## Process

1. **Gather nessisary information**: Look at the git history of the current branch and the current conversation for context.
2. **Ask Clarifying Questions**: If the reason for the changes are unclear ask the user for information and supporting documentation for the changes. Supporting documents and links should be included in the PR description.
3. **Draft a PR**: Open a PR on github for the current branch in draft mode.

## Target Audience

Assume the reader of the PR description is a teammate on another team with no context to the changes. Your goal is to communicatate clearly and effectively to them the context in which these changes were made so they can be an effective reviewer.

## Final instrcutions

1. Always open a PR in draft mode
2. Always keep the tone casual, but professional.
3. Take the user's answers and information into account
